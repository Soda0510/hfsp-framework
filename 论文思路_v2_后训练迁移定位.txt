【一句话定位】
用可验证奖励对开源 LLM 做后训练，把它训成一个通用的"算法设计器"；
HFSP 是训练域，HFSP 变体 / PFSP / JSP / VRP 是留出的迁移测试集；
核心贡献是证明**算法设计能力可通过后训练习得且可跨问题迁移**，
并量化迁移增益随问题距离的衰减。

【标题风格】朴素技术描述，强调"可验证奖励后训练 + 跨问题迁移"。
不要出现 RSI / 自进化 / 递归自我改进 等字样（见第十三节红线）。

==========================================================
二、为什么是这个定位（决策链）
==========================================================

■ 被否决的方案及原因

(1) 旧定位"双创新点：自进化框架 + 解决塌缩"
    → 创新点①已被抢：CALM (ICLR 2026) 进化 tuples + 持续微调；
      Surina et al. 2025 / Liu et al. 2025 用 DPO 微调提升启发式发现。
    → 创新点②已成红海：QDEvo (arXiv:2607.11916) 开篇动机就是
      "existing approaches suffer from mode collapse, converging to
      homogeneous populations that lack semantic diversity"，
      方案 = QD + 无界 archive（code embedding 度量语义多样性）+ 层次自反思。
      同向还有 HSEvo、MEoH、Pareto-Grid-Guided LLMs (AAAI-26)。
    → 结论：塌缩+多样性存档不能当主创新点。

(2) "选组件 ID"（原始做法）
    → 不是效果差，是**和核心 claim 逻辑冲突**：ID 编号在 VRP 上无对应物，
      迁移实验根本无法构造。既证伪不了也证实不了主张。必须废弃。

(3) LLaMEA 式"自由写整个算法"
    → 崩溃率：LLaMEA 用 GPT-4 系列尚有 18.7% 执行错误（843/4500），
      开源 Qwen 3B/7B 会更高，且崩溃候选照样消耗预算。
    → HFSP 约束远比 BBOB 硬（阶段分解/机器分配/工序顺序），
      自由代码会大量产出非法调度（非法 ≠ 差，是无法评分）。
    → 信用分配崩坏 + reward 方差爆炸，小模型学不动。

(4) "表示空间实证研究"作为**独立论文**——已否决，但方法本身保留
    → 否决理由（仅针对"独立成篇"这一形态）：
      · 不含模型训练 → 简历指向"受控实验研究"而非后训练管线，职业目标不对
      · 本质是分析型/负面结论型论文，AI 圈（NeurIPS/ICLR 侧）会问
        "so what，你提了什么新方法"；只在 EC/OR 圈吃得开，圈子受限
      · 与"自进化"叙事无关，LLM 在其中只是被测试的黑箱
    → ★但表示谱实验本身**必须做**，位置改为第 4.8 节：
      它是"凭什么选骨架+插槽"这个问题的唯一合法答案（数据，不是直觉），
      且承载一个能直接服务后训练 claim 的融合实验。详见 4.8。

■ 采纳的定位来自一个关键逻辑

  如果在 HFSP 上后训练的模型，能在没见过的 VRP 上设计出好算法，
  那说明它学到的不是"HFSP 知识"，而是"如何设计算法"这件能力本身。

  这句话同时满足三件事：
    · 是可证伪、可量化的科学主张
    · 天然是一个后训练泛化研究（= 目标岗位的日常工作）
    · 把 HFSP 从"我的问题"降级为"训练载体"，消解 scope 太窄的质疑

==========================================================
三、核心 claim 与验证结构
==========================================================

■ 主 claim
  后训练（SFT → DPO → RLVR）能让开源小模型习得可迁移的算法设计能力。

■ 三层对照（证明后训练有效）
  L1  零样本 base Qwen（不进化）
  L2  base Qwen + 进化（纯 prompting，无训练）
  L3  后训练模型 + 进化
  要求：L3 > L2 > L1，且差距显著（多 seed + 统计检验）。

■ 迁移对照（证明能力可迁移 —— 这是论文的核心图）
  在每个 held-out 问题上比：后训练模型 vs base Qwen vs EoH/ReEvo 报告结果。
  画「迁移增益 vs 问题距离」曲线。

  ★ 目标不是"打赢所有人"。只要在 VRP 上
    「后训练 Qwen > 未训练 Qwen」成立，迁移 claim 就立住了。
    打不过专门在 VRP 上做进化的 EoH 是可以接受且应当如实报告的。

■ 关键 claim 的门槛（不是 SOTA 门槛）
  进化循环不需要打赢 PRTS/CSA，但**必须产出可学习的数据**：
    (a) 质量有梯度 —— 否则 DPO 无 (y_w, y_l) 可构造
    (b) 行为有多样性 —— 否则微调后只会输出同一套模板，迁移必然失败
    (c) 量足够 —— LoRA DPO 大致需要千级别偏好对
  ⇒ "进化不用很强"成立；"进化可以继续塌缩"不成立。

==========================================================
四、技术方案：骨架 + 插槽 + 契约
==========================================================

■ LLM 干什么
  在固定契约下**写决策函数代码**（函数体），不是选 ID，不是写整个算法。
  数值参数不由 LLM 猜 —— 交给 SMAC（见第 4.4）。
  合法性不由 LLM 保证 —— 交给骨架里的解码器。

■ 4.1 骨架四条设计目标（按优先级）
  1. 合法性由骨架保证，不由 LLM 保证
  2. 跨问题同构 —— HFSP 与 VRP 骨架必须同形，否则迁移 claim 没有载体
  3. 预算与超时由骨架强制 —— LLM 写的代码不能跑飞
  4. 行为轨迹自动记录 —— 免费的 reward shaping 素材

■ 4.2 骨架结构（你写死，LLM 不可改）

  class SearchState:            # 只读，让 LLM 能写自适应策略
      iter, evals_used, evals_budget
      progress                  # = evals_used / budget ∈ [0,1]
      cur_cost, best_cost, iters_since_improve

  def solve(instance, budget, seed, slots, params):
      rng = Random(seed)
      ev  = MeteredEvaluator(instance, budget)   # 计数 + 超预算抛异常
      st, trace = SearchState(), Trace()
      try:
          cur = validate(slots.construct(instance, params, rng), instance)
          cur_cost = ev(cur); best, best_cost = cur, cur_cost
          while True:
              cand = validate(slots.perturb(cur, instance, st, params, rng), instance)
              cand = validate(slots.improve(cand, instance, st, ev, params, rng), instance)
              c = ev(cand)
              if slots.accept(cur_cost, c, st, params, rng):
                  cur, cur_cost = cand, c
              if c < best_cost:
                  best, best_cost = cand, c; st.iters_since_improve = 0
              st.step(); trace.record(st)
      except BudgetExhausted:
          pass                                   # 正常出口
      return best, best_cost, trace

■ 4.3 四个插槽契约
  construct(instance, params, rng)                -> Solution
  perturb (sol, instance, state, params, rng)     -> Solution
  improve (sol, instance, state, ev, params, rng) -> Solution
  accept  (cur_cost, new_cost, state, params, rng)-> bool

  设计理由：
  · ev 作为计量评估器传入 improve：局部搜索必须能评估候选解。
    做成计量的可同时解决 预算强制 / 同预算公平对比 /
    让 LLM 自然写"改进到预算耗尽"。
  · state 只读：给 LLM 写自适应策略的能力，不给它污染全局的机会。
    注意 LLaMEA 的发现——LLM 不知道总预算故无法按阶段调步长；
    我们显式给出 progress，这是一个小改进点。
  · validate 做契约检查 + 修复：HFSP 检查是否全部工件的合法排列，
    不合法则修（去重+补漏）或按类型报错。
  · 错误类型必须分开：语法错 / 契约违反 / 超时 / 运行时异常。
    分类反馈比一坨 traceback 有效，且本身可做消融。
  · 墙钟超时要单独加：LLM 若写出不调 ev() 的死循环，预算机制拦不住。

■ 4.4 参数交给 SMAC（必做）
  LLM 输出两样东西：① 插槽函数代码（结构）② ConfigSpace 字典（数值参数声明）。
  数值全部交给 SMAC/irace 调，LLM 每次调用都花在结构上。
  依据：LLaMEA-HPO 消融——默认参数 AOCC 0.25~0.50，SMAC 调完 0.45~0.52，
        差约 0.2；原文明言 "much of the LLM-driven optimization in the
        baselines LLaMEA (without HPO) and EoH is actually the tuning of
        the different hyper-parameters"。
  对本项目的双重价值：省预算 + 让训练数据变干净
  （同结构不同参数不再被当成不同样本，DPO 比的是真实结构差异）。

■ 4.5 表示 vs 解码器（最关键的权衡）
  放进"表示"的 LLM 能设计；放进"解码器"的 LLM 碰不到。
  HFSP 建议起点：
    表示   = 工件排列 π
    解码器 = 逐阶段列表调度，每阶段分配给最早可用机器（你写死）
    代价   = makespan
  代价：机器分配规则被固定了（那本来也是一个设计维度）→ 见课程阶段 C。

■ 4.6 课程（别一上来全开，信用分配会淹死你）
  阶段A：只开 improve（或 perturb），其余用手工最优版固定。
        目的：跑通全流程、验证后训练有效的最小闭环。
  阶段B：开 improve + perturb + accept，引入信用分配
        （轮流把某插槽换回手工版，看性能掉多少）。
  阶段C：全开 + 增设 assign_machine 插槽，允许改控制流。
  ★「开放插槽数 vs 搜索难度/收益」这条曲线本身是论文的一个维度——
    现有工作基本固定"生成一个函数"，没人做。

■ 4.7 旧组件库的三个新身份（不白做）
  ① few-shot 示例 / 初始种群
     ⚠ LLaMEA 作者自己的警告：示例代码会把搜索偏向相似算法。
       故示例要给多样的几个，并做消融看示例对多样性的影响
       （这个观察本身可写进论文）。
  ② 手工基线（必须报的对照）
  ③ 领域先验（prompt 里写"HFSP 常用邻域：insertion / swap /
     critical-path based"，给知识不给答案）

■ 4.8 表示谱：骨架+插槽的承重论证 + 与后训练的融合点

  ▸ 为什么必须做
    v2 选定"骨架+插槽+契约"这一表示，审稿人必然问：
      凭什么？为何不用自由代码（表达力更强）？为何不用 ID（更可控）？
    这个问题的答案只能是数据，不能是直觉。
    位置：写在 method 之前作为 motivating experiment，或作为一节 ablation。
    地位：不是论文贡献，是**贡献的承重论证**。

  ▸ 核心主张（三角权衡）
    LLM 驱动算法设计的成败主要由**设计空间的表示**决定，
    而非进化机制的精致程度。存在不可兼得的三角：
        表达力 ↔ 可搜索性 ↔ 合法率

    现成的强对比（无需新实验即可写进 intro）：
      · LLaMEA：(1+1)、种群 1、无交叉、多样性机制仅"历史算法名单去重"，
        但在自由 Python 空间持续爬升，赢过 52128 变体中选出的 CMA-best；
        代价是 18.7% 代码崩溃率（自由空间不免费）。
      · 本项目旧版：有种群/精英保留/记忆，但在封闭 ID 菜单里几代即死。
      ⇒ 机制更精致却更差 ⇒ 瓶颈在表示，不在机制。
    现有文献从未回答这个困惑，因为每篇工作各自固定一种表示，无人横切对照。

  ▸ 表示谱（做减法版：只做 a / c / d 三档）
      (a) ID 菜单          表达力最低   合法率 100%    ← 项目旧版所在
      (b) 参数化模板       低          高            ← 跳过，信息量最低
      (c) 语法约束/领域DSL 中高        高            ← 骨架+插槽所在
      (d) 自由 Python      最高        ~80%          ← LLaMEA 所在
    ★ 只在课程阶段 A 的单插槽设定下做 → 每套表示实现量都不大。

  ▸ 测量维度
    最终 PRD、进化曲线斜率、有效变异率、合法率、行为多样性、oracle gap。

  ▸ 杀手实验（若成立，就从"分析"升级为"方法"）
    证明 (c) 在同预算下**既有 (d) 的爬升能力、又有 (a) 的合法率**。

  ▸ ★★ 融合点：表示的可用边界是模型能力的函数

    这是让表示轴**直接服务后训练 claim** 的设计，两条路线由此不再是取舍。

    假设：
      · base Qwen 3B 在自由 Python 空间 → 崩溃率高、质量差 ⇒ (d) 对它**不可用**
      · 后训练 Qwen 3B 在自由 Python 空间 → 崩溃率降、质量升 ⇒ (d) 变**可用**
    ⇒ 结论：**后训练不只提升了同一表示下的性能，它扩展了模型可用的表示空间。**

    做法：同一条表示谱，跑 base 模型与后训练模型各一遍，画两条曲线，
          量化"可用边界"右移了多少。

    三个好性质：
      1. 可测、可量化，不依赖主观判断。
      2. 把"合法率 vs 条件质量"陷阱（见 A2）反过来变成武器：
         在这个框架下**合法率提升本身就是有意义的结果**——
         它意味着模型能在更有表达力的空间里工作了。
         （条件质量仍必须一起报，A2 的要求不取消。）
      3. 是后训练领域听得懂的叙事形态：
         "训练让模型跨过能力阈值，解锁了原本不可用的操作空间"。

  ▸ 附带收益
    项目旧版在 ID 菜单上的失败由此获得正式学术位置——
    它不再是"走错了路"，而是表示谱最左端的数据点，
    用于说明表达力不足会发生什么。

  ▸ 明确不做
    不把表示谱做成独立论文（理由见第二节 (4)）。

五、迁移阶梯（核心实验设计）
==========================================================

  距离    目标问题                          检验          成本
  训练域  HFSP 静态 / makespan              基础能力       —
  极近    换目标函数 → total flowtime       目标泛化      零成本
  近      HFSP 变体（不相关机器/阻塞/
          调整时间 setup times）            约束泛化      低
  中      PFSP / JSP（Taillard 等）         同族泛化      中
  远      VRP / online bin packing          跨问题族泛化  高

  产出：「迁移增益 vs 问题距离」曲线 = 论文核心图。
  比任何单点数字都有力，且能抵御"VRP 那个结果是巧合"的质疑。

  ⚠ VRP + Guided Local Search 是 EoH / ReEvo / FunSearch 的主战场，
    有现成强基线（好事：迁移结果才可信）。但预期打不过它们，见第三节。

  跨问题同构性（迁移 claim 的唯一技术支撑，必须在论文里显式论证）：
            HFSP              VRP
    表示    工件排列          客户巨型路径
    解码器  逐阶段列表调度    按容量切分路径
    代价    makespan          总距离
    插槽    四个，签名同形    四个，签名同形
    prompt  除"问题描述 + 类型签名"外完全一样

六、后训练管线
==========================================================

  数据来源：进化循环产出的 (插槽实现, 实例集, PRD) 三元组。
  偏好对构造：同一插槽 + 同一实例集下，两个实现的 PRD 差异
              → 天然的 (y_w, y_l)。这是 DPO 数据的免费来源。

  阶段1  SFT     ——（可选）先用高质量样本教格式与基本套路
  阶段2  DPO     —— 本地可跑（MLX，1.5B/3B + LoRA）。先跑通 pipeline。
  阶段3  RLVR/GRPO —— 需 GPU（租 AutoDL，4090 约 2 元/时）。
                    reward = -PRD（或归一化后的），评估器即 verifier。

  为什么 RLVR 在这里特别干净：
    makespan 精确可算 → 评估器天然是 verifier
    → 无需训 reward model → 不存在 reward hacking。
    这是与 CALM（用 DPO）的一个实质差异。

  为什么这个输出形态对训练友好：
    · 输出短（一个函数几十行，不是几百行整算法）→ 小模型吃得住
    · 格式统一（签名固定）→ SFT 数据干净，DPO chosen/rejected 可比性强
    · 奖励可归因（只改一个插槽）→ RLVR reward 噪声小

==========================================================
七、塌缩的新身份：训练数据质量问题
==========================================================

  原来：塌缩 = 性能问题（要解决它才能打赢基线）→ 该路已被 QDEvo 抢占
  现在：塌缩 = 数据质量问题（塌缩数据做 SFT/DPO 会把塌缩固化进权重）

  ⇒ 差异化定位：
     QDEvo 在**搜索侧**做多样性（QD + code embedding archive）
     本工作在**训练侧**做 diversity-aware data curation
     同一个病、两个不同治疗位置 → 可互相引用而非竞争。

  ★ 一个可用来质疑 QDEvo 方法论的观察（且我们有数据）：
    QDEvo 用 code embedding 度量语义多样性；
    但"池子同质"现象说明——代码不同，行为可以完全相同。
    code embedding 上散开的两个算法，实例上表现可能一模一样。
    ⇒ 多样性应在**行为空间**度量，不是代码空间。
    这条既是 related work 的批评点，也是数据筛选的方法依据。

八、实验矩阵
==========================================================

  A. 训练侧
     A1  三层对照 L1/L2/L3（多 seed + 统计检验）
     A2  ★指标必须拆两个分开报：
         · 合法率（生成代码能跑通的比例）
         · 条件质量（在能跑通的样本里的 PRD）
         若只有合法率升、条件质量不变 ⇒ 后训练只教了格式，不是设计能力。
         这是审稿人一击致命的地方，必须提前堵。
         ※ 注意与 4.8 融合点的关系：在"可用边界"框架下合法率提升
           本身有独立意义，但这不豁免本条——两个指标始终分开报。
     A3  数据筛选消融：全量 vs 只留最优 vs 多样性感知筛选
     A4  灾难性遗忘检查：训完跑几个通用代码/数学题看有没有退化
     A5  过拟合监控：训练中就监控 held-out 问题表现，当早停信号

  B. 搜索侧
     B1  同预算对比 SMAC / irace（必须）
     B2  LLaMEA-HPO 式"参数 vs 结构"分离消融（必须）
     B3  课程消融：开放插槽数 1 → 3 → 全开
     B4  few-shot 示例对多样性的影响（呼应 LLaMEA 作者的警告）
     B5  表示谱横切（见 4.8）：(a) ID 菜单 / (c) 骨架+插槽 / (d) 自由 Python
         同预算对比，测 PRD / 曲线斜率 / 有效变异率 / 合法率 / 行为多样性。
         用途：回答"凭什么选骨架+插槽"。
     B6  ★可用边界实验（见 4.8 融合点）：
         同一表示谱下 base 模型 vs 后训练模型各跑一遍，
         量化可用边界右移量。这条同时服务 A（训练有效）与 B（表示选择）。

  C. 迁移侧
     C1  迁移阶梯全表（第五节）
     C2  迁移增益 vs 问题距离曲线（核心图）
     C3  每个 held-out 问题上：后训练模型 vs base vs EoH/ReEvo 报告值

  D. 外部有效性
     D1  上标准 benchmark：CO-Bench / HeuriGym / BLADE / LLM4AD
         （只在 HFSP 上做，好 venue 会说 scope 太窄）
     D2  规模泛化：训 10–60 工件，测 120–240

九、必须堵的洞（按致命程度）
==========================================================

  [1] BKS 重算 —— 最致命
      PRD 4.59% 可能对着旧表算出。PRTS 2024 (COR) 把 FV&F testbed
      240 实例中的 101 个刷新了；PLOS One 2025 (IPMMPO) 又改进部分。
      BKS 更新链：FV&F 2020 原论文 → Lin et al. 2021 ESWA 183:115422
      → FV&F 2022 ESWA → PRTS 2024 COR → PLOS One 2025。
      做法：收集各论文对比表，逐实例取最小值组成最新 BKS 表，重算 PRD。
      注：不影响 oracle gap 诊断（同表下相对比较），可并行做。

  [2] SMAC/irace 同预算对照 + 参数/结构分离
      LLaMEA-HPO 已把"很多增益来自调参"做实，审稿人有充分理由要求
      你证明增益不是 SMAC 单独调参就能拿到的。躲不过。

  [3] 合法率 vs 条件质量分开报（见 A2）

  [4] 多 seed + 防胜者诅咒
      单 seed 评估噪声大。挑算法与报成绩要用不同 seed 组，
      否则 oracle / 最优选择会虚高（详见 Oracle_Gap诊断方案.txt）。

  [5] 标准 benchmark（见 D1）

十、相关工作与差异化

■ 必读（按优先级）
  1. LLaMEA-HPO (van Stein, Vermetten, Bäck; ACM TELO 2025,
     doi 10.1145/3731567; arXiv:2410.16309) —— 精读
     重点：结构变异 vs 参数变异的边界如何定义；SMAC 对照怎么设计。
  2. Code Evolution Graphs (van Stein, Kononova, Kotthoff, Bäck) —— 精读方法
     量化 LLM 变异究竟改了什么（三类变异模式）；
     是"池子同质"分析的现成工具与写法参考。
  3. QDEvo (arXiv:2607.11916) —— 精读，重新差异化（见第七节）
  4. CALM (ICLR 2026) —— 精读
     ★待核实：CALM 有没有做跨问题迁移实验？
       这决定我们"迁移"这一 claim 的新颖性表述，不要凭印象写 related work。
  5. Surina et al. 2025 / Liu et al. 2025（DPO 微调提升启发式发现）
  6. LLaMEA 主文 (TEVC 2025, 29(2):331-345) —— 泛读框架与 prompt 设计

■ LLaMEA 事实备忘（曾被我记错，已更正）
  LLaMEA 是**正面结果**：BBOB 5D 上生成的 ERADS 优于 CMA-ES，
  并优于从 52128 个 CMA-ES/DE 变体中选出的 CMA-best；
  拿了 GECCO 2024+2025 Many-Affine BBOB 竞赛第一、Humies 2025 银奖、
  IEEE CoG Planet Wars 第三。
  两处水分（对我们有用）：
    · Table I 的 EAF AUC 实际是 CMA-best 0.742 > ERADS 0.733；
      "超过 CMA-best"指曲线末端点，不是整条曲线。
    · ERADS 不泛化到高维（5D 好，10/20D 不行），作者自己划了范围。
  机制备忘：(1+1)-EA，种群 1，无交叉，多样性机制只有"历史算法名单去重"；
    变异 = 一次 prompt（"Either refine or redesign to improve the algorithm"）；
    T=100 次 LLM 调用/轮；仅测 gpt-3.5-turbo / gpt-4-turbo / gpt-4o
    （**一个开源模型都没测** ← 我们的位置）；
    崩溃候选 fitness 记 0 且照样消耗预算；
    (1+1) 对 GPT-4 有益、对 GPT-4o 有害。
  作者自述局限（可引用）：依赖 prompt 质量、可能限制生成多样性；
    "the LLM uses existing algorithms, algorithm components and search
    strategies"；最好的算法多为 DE 变体或 CMA-DE 混合，疑为模型偏好。

■ 我们的差异化（四条，按强度）
  1. 跨问题迁移作为核心 claim（★待核实 CALM 是否已做）
  2. RLVR + 组合优化 verifier（CALM 用 DPO；我们的评估器天然是 verifier）
  3. 开源小模型（LLaMEA 全程闭源 GPT；QDEvo/EoH 亦用 GPT-4o 级）
  4. 训练侧 diversity-aware data curation（vs QDEvo 的搜索侧 QD）

■ 领域格局速记
  主干：FunSearch (Nature'24) → EoH (NeurIPS'24) → ReEvo → LLaMEA →
        QDEvo / HSEvo / MEoH / Pareto-Grid-Guided (AAAI-26)
  benchmark：CO-Bench (AAAI'26)、HeuriGym (ICLR'26)、LLM4AD、BLADE
  第二篇方向注意：DSevolve (2026.03) 触碰算法池方向

十一、执行路线图
==========================================================

■ 阶段 0（本地，最高优先级，2~3 周）——「定性」
  0.1 跑 oracle gap 诊断（脚本已就绪：oracle_gap.py）
      判据：交互项/seed 噪声比 >2 有真互补 / <1.3 同质
  0.2 给历史算法加行为指纹，验证"代码多样但行为同质"是否为真
      → 这是第七节整个论证的地基
  0.3 顺手处理诊断报告里的 bug 类信号
      （oracle PRD 为负 → 查 BKS 或评估器；进化曲线不单调 → 查精英保留）
  验收：知道池子是健康还是同质；知道行为度量能否区分它们。

■ 阶段 1（本地，4~6 周）——「重建输出层」
  1.1 实现骨架 + 4 个插槽契约 + validate + Trace（第四节）
  1.2 把旧组件重写为符合签名的独立函数（→ 手工基线 + few-shot 示例）
  1.3 接 SMAC/irace（ConfigSpace 由 LLM 输出）
  1.4 课程阶段 A：只开 improve，跑通「进化 → 数据 → DPO → 提升」最小闭环
  1.5 表示谱三档实现（见 4.8）：(a) ID 菜单沿用旧代码、(c) 骨架+插槽、
      (d) 自由 Python。均在阶段 A 单插槽设定下，实现量小。
      → 跑 B5 横切对比，拿到"凭什么选 (c)"的数据。
  验收：L3 > L2 > L1 成立（哪怕幅度小）；合法率与条件质量分开可测；
        表示谱三档均可运行且 B5 有明确结论。

■ 阶段 2（本地 + 少量租卡，6~10 周）——「做实数据与训练」
  2.1 扩到课程阶段 B，引入信用分配
  2.2 diversity-aware data curation（用行为指纹而非 code embedding）
  2.3 DPO 消融（数据筛选策略 A3）
  2.4 BKS 重算并回填所有 PRD 数字
  2.5 ★可用边界实验（B6）：DPO 后的模型重跑表示谱三档，
      与阶段 1.5 的 base 曲线对比，量化边界右移。
      → 这是 4.8 融合点的实证，也是"后训练扩展了可用表示空间"这一 claim 的证据。
  验收：数据筛选消融有明确结论；PRD 数字对着最新 BKS 表；
        可用边界是否右移有明确结论（右移了 → claim 成立；没移 → 如实报告，
        退回"同表示下性能提升"的较弱 claim，不硬推）。

■ 阶段 3（租卡）——「RLVR + 迁移」
  3.1 GRPO/RLVR，reward = -PRD
  3.2 迁移阶梯从近到远逐级做（先零成本的换目标函数，最后 VRP）
  3.3 上标准 benchmark
  验收：迁移增益 vs 距离曲线成形。

■ 第二篇（复用全部基建）
  每实例自适应选择：实例特征 + 条件生成、算法池协同进化 +
  学习型每实例选择器、规模泛化。
  ★ 若阶段 0 诊断落在"池子健康（交互/噪声 >2）"，说明每实例选择
    有结构性保证的增益 → 可考虑把第二篇提前或并入第一篇。

十三、红线
==========================================================

  1. RSI / 自进化 / 递归自我改进：只放 intro 与 related work 做叙事包装，
     **不进标题、不进核心 claim**。审稿人对过度包装的自进化叙事很警惕。
     叙事归叙事，claim 归 claim。
  2. "算法工程师/设计师"的故事化包装可以用，但技术主张必须朴素可验证。
  3. 不要声称"我的方法能生成更强算法"除非数据支持。
     主张是"后训练能提升设计能力并可迁移"，这是更低且更可守的门槛。
  4. 阶段 0 诊断数字出来之前，不要再改进化机制、不要上 DPO。
     （若数据已塌缩，微调会把塌缩固化进权重。）
