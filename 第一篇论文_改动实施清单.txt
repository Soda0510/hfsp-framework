==========================================================
改动 1：评估器——多 seed + 排名
==========================================================

【为什么】单 seed 噪声大，候选间差距常小于随机波动，
进化后期 LLM 看到的候选"在噪声里没区别"，选择压力归零。

【怎么做】
1. evaluate(algorithm, instance_set, n_seeds=10)：
   - 对训练集每个实例跑 n_seeds 次（不同随机种子），
     取 mean PRD + std；
   - 汇总全部实例得该算法的总 PRD。
2. 生成种群内"排名"：
   - 把本代所有候选按 PRD 排序，记 rank 和相对改进量；
   - 喂给 LLM 的用【排名 + 相对 PRD 改进】，
     不要裸 makespan。
3. 训练集做选择/进化，测试集只在最终验证时碰一次。

【验收点】
- 同一算法重复评估两次，PRD 差异 < 0.3 个百分点
- 记录"排名稳定性"：相邻两代 top-K 变化合理
  （不再出现"永远同一个最好"）

【注意】种子用固定列表（如 1..10），保证可复现；
计算预算按"总评估次数"记账，后面与 SMAC 同预算对比要用。

==========================================================
改动 2：表示层——ID 串 → JSON 染色体
==========================================================

【为什么】ID 是死的没法"变"；JSON 每个字段是一个槽位，
LLM 可以改一个字段，这是变异/交叉的地基。

【怎么做】
1. 定义染色体 JSON（按你的组件清单填充字段名）：
{
  "init": "NEH",
  "local_search": "insertion_first",
  "neighborhood_order": ["swap", "insert", "block"],
  "destruction_size": 4,          // 数值槽位
  "reconstruction": "NEH_insert",
  "acceptance": "record_to_record",
  "initial_temperature": 2.0,     // 数值槽位
  "cooling": "geometric",
  "crossover": "POX",
  "mutation": "swap"
}
2. 槽位分两类：
   - 离散槽位：取值必须来自候选列表；
   - 数值槽位：取值必须在给定范围内。
3. 写染色体 → 可执行算法的编译函数：
   每个槽位 ID 映射到已实现的算子代码。
4. 写合法性校验函数 validate(chromosome)：
   - ID 在候选集内、参数在范围内、字段齐全，
     否则丢弃该候选或触发重试。

【验收点】
- 任意合法 JSON 能无错编译成可运行算法并出结果
- 非法 JSON（错误 ID/超范围参数）被正确拦截

==========================================================
改动 3：LLM 引擎——变异 / 交叉（阶段 3 先上轻/中档）
==========================================================

【三档变异定义】
- 轻：换一个离散槽位的 ID（仍属"选"）
- 中：调一个数值参数 / 改邻域顺序
- 重：改写或新造一个算子的逻辑（阶段 5 再做）
每代变异比例建议：60% 中 / 30% 轻 / 10% 重

【系统提示（固定，可直接抄）】
"""
你是混合流水车间调度（HFSP）领域的算法设计专家，
精通元启发式算法（遗传算法 GA、模拟退火 SA、迭代贪心 IG），
并理解各算子在何种问题结构下有效。

## 问题背景
- 混合流水车间：n 个工件依次经过 s 个阶段，
  每阶段有 m_s 台并行同速机器。
- 目标：最小化最大完工时间 makespan。
- 领域直觉（设计算法时主动运用）：
  - 瓶颈机器：负荷（加工时间之和）最大的机器，
    缩短 makespan 的关键在削瓶颈。
  - 关键路径：决定 makespan 的那条工序链，
    局部搜索应优先扰动关键路径上的工件。
  - NEH 原则：总加工时间大的工件优先安排，
    插入时贪心取最好位置。
  - 破坏重建（IG）：随机移除 d 个工件再重新插入，
    能有效逃离局部最优。
  - 记录到记录（RTR）：接受比当前最优差但不超过
    阈值 δ 的解，平滑逃离局部最优。

## 输出格式（铁律，违反即重试）
- 只输出一个 JSON 对象，放在 ```json 代码块内。
- JSON 之外的任何解释文字都不允许；
  理由必须写进 JSON 的 "reason" 字段。
"""

【用户消息模板：中/轻变异】
"""
## 当前最优算法配置
```json
{当前配置 JSON}
```
它在训练集上的平均 PRD 为 {PRD}%，种群内排名第 {rank}。

## 任务：做一次「中/轻」变异
只能做以下之一，且只改 1 处：
1) 把某个离散槽位的算子 ID 换成候选列表里的另一个
2) 调整一个数值参数（在给定范围内）
3) 改变邻域遍历顺序

## 候选与范围
- init: [NEH, random, Palmer, CDS]
- local_search: [insertion_first, insertion_best, swap_first]
- neighborhood: [swap, insert, inverse, block]
- acceptance: [metropolis, record_to_record, threshold]
- crossover: [POX, JOX, two_point]
- mutation: [swap, insert, inverse]
- destruction_size: 2~10 整数
- initial_temperature: 0.5~5.0

## 输出
```json
{"config": {新配置}, "reason": "一句理由"}
```

## 范例 1
输入: {"init":"random","acceptance":"metropolis"}
输出: {"config":{"init":"NEH","acceptance":"metropolis"},
"reason":"NEH 按总加工时间降序+贪心插入，初始解质量远好于随机"}

## 范例 2
输入: {"destruction_size":4}
输出: {"config":{"destruction_size":6},
"reason":"增大破坏规模能更彻底逃离局部最优，代价是重建更慢"}

现在开始变异。
"""

【用户消息模板：交叉】
"""
## 两个精英配置
A: {json A}
B: {json B}

## 任务：杂交生成新配置 C
每个槽位从 A 或 B 选一个（允许对某个槽位做一次小改动），
继承两者优点。

## 输出
```json
{"config":{C}, "reason":"一句理由"}
```
"""

【输出解析（Qwen 防翻车五条）】
1. 正则抓 ```json ... ``` 代码块；
2. 代码块外内容全部丢弃，json.loads() 解析；
3. 解析失败 → 带报错信息重问：
   "你上次输出无法解析，错误是 XXX，请严格按格式重新输出"；
4. 解析成功 → validate() 校验 ID/范围/字段，
   不合规同样按失败重试或丢弃；
5. 终极方案：vLLM 部署 Qwen 时开 guided_json 约束解码，
   从解码层强制合法 JSON，可省掉 1-4 的脏活。

==========================================================
改动 4：多样性控制（防塌缩，阶段 4）
==========================================================

【为什么】"选出一个算法永远最好"就是塌缩；
精英保留 + 近亲繁殖导致种群同质化，搜索死亡。

【多样性指标（三选一即可，建议先上 Jaccard）】
- 组件重合度：1 - Jaccard(候选组件集合, 种群组件集合)
- 唯一结构数：种群中互不相同的染色体数 / 种群大小
- 香农熵：种群组件分布的熵

【机制 A：相似度惩罚（简单，先做）】
fitness' = fitness - λ × max_sim(候选, 种群成员)
- λ 从 0.01 调起；sim 用组件重合度；
- 太像已有精英的候选被压分，保留"稍差但不同"的个体。

【机制 B：帕累托（进阶）】
同时优化 (PRD, 多样性)，取非支配前沿 + 拥挤距离
选下一代，兼顾质量和探索。

【进化器每代流程（取代现在的"只留最好"）】
1. 评估上一代 → 取 top-K 精英（K=5，别只留 1）
2. 对每个精英跑变异（比例 60/30/10）
3. 随机配对精英跑交叉，生成若干候选
4. 新候选 + 旧精英一起打分（含多样性惩罚）
5. 保留 top-K 进下一代

【验收点】
- 种群唯一结构数不塌到 1（≥ K/2 为健康）
- best PRD 不再"永远不变"，至少出现新最优或保持多样性

【重变异 prompt：新造算子】
"""
## 当前算法的「局部搜索」算子伪代码
```python
{算子伪代码}
```

## 任务：做一次「重」变异——设计一个新的局部搜索算子
保持接口不变，目标让它更能逃离局部最优。可以：
- 引入新邻域：块交换、k-opt 变体、基于关键路径的操作
- 加入接受准则：小概率接受恶化解
- 改搜索策略：first/best improvement、VND 变邻域下降

## 输出
```json
{"name":"新算子名", "pseudocode":"Python 伪代码",
 "reason":"相比原算子的优势"}
```

## 范例
输入: 原算子 = 遍历所有工件对做 swap，取 first-improvement
输出: {"name":"critical_path_block_insert",
"pseudocode":"def ls(x):\n  cp = critical_path(x)\n  for block in blocks(cp):\n    for m in machines:\n      y = move_block(x, block, m)\n      if makespan(y) < makespan(x): return y\n  return x",
"reason":"只在关键路径块上搬移，扰动更有针对性，收敛更快"}
"""

【Archive 记忆库】
- 每代写入：最好配置 + LLM 生成的一句"洞察"
  （"为什么这个算子/组合在这个实例分布上有效"）
- 洞察文本拼进下一代的系统提示/用户消息，
  让 LLM 基于经验而非从零想（ReEvo 思想）
- 积累的 (配置, 洞察, 表现) 三元组，
  同时是后面 DPO 数据的原料

改动 6：DPO 自训练闭环（阶段 6，论文"自"字核心）
==========================================================

【为什么不用 naive SFT】
生成数据已塌缩 → 普通 SFT 把塌缩固化进权重；
DPO 用偏好对教"比较能力"，天然抗塌缩，
且"用进化数据做偏好对齐训练算法设计模型"无成熟先例。

【数据构造】
1. 进化过程天然产生偏好对：
   同一父代的两次变异 → 评估 → 胜者/败者；
2. 构造 (prompt, win_config, lose_config) 三元组：
   - prompt = 当时的系统提示 + 用户消息（当前配置+表现+指令）
   - win = PRD 更好的那个输出
   - lose = PRD 更差的那个输出
3. 数据要求：
   - 几千对规模；
   - 必须包含大量失败样本（这是抗塌缩的关键）；
   - 失败样本的 reason 也保留（教模型"为什么差"）；
   - 刻意保留结构多样的样本，不要只留 top 解。

【训练】
- Qwen + LoRA 微调即可（省算力，效果足够）；
- 用标准 DPO loss（对比 SFT + 偏好项）；
- 严格按训练/测试实例隔离：DPO 数据只来自训练集实例。

【三层对照（证据 3 的实验设计）】
A. 零样本：原始 Qwen 直接选/生成（无进化、无训练）
B. 微调前：原始 Qwen 跑完整个进化流程，取 best
C. 微调后：DPO 后的 Qwen 再跑同样流程，取 best
结论必须：C > B > A，且报告在测试集上的 PRD。

【风险预案】
- 若 DPO 后无增益：检查偏好对质量（噪声太大？）、
  数据多样性（塌缩了？）、LoRA 参数；
- 若仍无增益：如实报告"自训练无增益的条件分析"，
  退守第一篇的防塌缩主线（先分后合策略兜底）。

【升级路线：DPO → RLVR/GRPO 两步走（2026-08-31 补充）】
第一步（先跑通）：DPO——数据从进化过程攒偏好对，
  LoRA 训练，稳定可控，先拿到"微调后有增益"的证据。
第二步（升级版）：RLVR/GRPO——评估器就是 verifier，
  reward = -PRD（或相对基线改进量），
  模型在线"生成算法 → 评估 → 更新 → 再生成"，
  形成真正持续运转的自进化闭环。
  - 优势：天然更强的探索性（探索出新东西本身有奖励）；
    可在线持续运行；比 DPO 更贴合"自进化"叙事。
  - 风险：训练不稳定（奖励稀疏/方差大，多 seed 评估
    在此处更重要）；算力要求比 DPO 高一截；
    塌缩风险仍在——奖励里应加多样性项。
  - 工程：Qwen 生态对 GRPO 支持好（trl / vLLM /
    verl 等现成框架）。
  - 决策点：DPO 增益小或想要更硬的论文故事时上 RLVR。

【Exp 1 基线重测】
- 多 seed 下重测：手工 NEH/IG/SA/GA、当前 LLM 系统

- 卖点：证明"塌缩是 LLM 算法进化的通用失败模式，
