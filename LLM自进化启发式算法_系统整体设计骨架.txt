==========================================================
LLM 自进化生成启发式算法 — 系统整体设计骨架（HFSP）
记录日期：2026-08-31
==========================================================

【项目背景】
- 问题：混合流水车间调度（HFSP），最小化 makespan
- 方法：把 GA/SA/IG 拆成组件，LLM 按 ID 选择组件组成算法
- 模型：开源 Qwen（后续微调）
- 数据：HFSP benchmark 480 算例，训练/测试集分离，规模 10-240
- 现状：LLM 选的算法比手工算法好，PRD 4.59% vs BKS；
  但进化塌缩——选出一个最好算法后 10 代不再提升
- 诊断：ID 菜单空间太小太封闭；单 seed 评估噪声大；
  精英保留无多样性控制 → 塌缩

==========================================================
一、总览：两条闭环套在一起
==========================================================

                     ┌──────────────────────────────────────────────┐
                     │          外环：自训练（SFT）                    │
                     │  进化沉淀的高质量 (实例→算法) 数据               │
                     │        │                                      │
                     │        ▼                                      │
                     │    微调 Qwen ──────► 更强的 LLM                │
                     └────────┼─────────────────────────────────────┘
                              │ （更新模型，反哺内环）
                              ▼
┌──────────────────── 内环：进化 ────────────────────────────────────┐
│                                                                   │
│  种群(一组算法配置) ──► LLM引擎(变异/交叉/生成) ──► 新候选          │
│      ▲                                              │              │
│      │                                              ▼              │
│      │                                          评估器              │
│      │                                     (多seed → PRD/排名)     │
│      │                                              │              │
│      └────── 选择 + 多样性控制 ◄─────────────────────┘              │
│                                                                   │
│   记忆库 Archive：历史最好解 + 洞察文本（可喂回 prompt）              │
└───────────────────────────────────────────────────────────────────┘

- 内环 = 进化：短周期，跑 10 代，目的是在"算法空间"里搜
- 外环 = 自训练：长周期，用内环沉淀的数据微调模型，
  让"搜的人"本身变强
- 现有系统只有内环的一半（种群 → LLM 选 → 评估 → 精英保留），
  缺：LLM 生成能力、多样性控制、记忆库、外环正确接法

==========================================================
二、七个模块
==========================================================

1. 算法表示层（Representation）
   - 职责：定义"一个算法"长什么样——进化的"基因"
   - 现状：一串 ID
   - 目标：JSON 染色体（离散槽位 + 数值槽位），
     逐步演进到"代码片段"
   - 这是地基，决定 LLM 能搜多大空间。
     ID 是最小的空间，代码是最大的。

2. 组件库（Component Library）
   - 职责：存所有可用算子，每个算子带一段语义描述
   - 形式：{ID, 名字, 描述:"擅长什么/什么场景好", 接口}
   - 语义描述是喂给 LLM 的"弹药"，没有它 LLM 就是盲选/盲改

3. LLM 引擎（LLM Engine）
   - 职责：把"当前配置 + 表现 + 指令"变成"新配置/新算子"
   - 内部：变异、交叉、重生成三个 prompt 接口
   - 这一层只管"生成"，不管"好不好"——评估交给下一层

4. 评估器（Evaluator）
   - 职责：跑一个算法，给出可靠分数
   - 要点：多 seed 取均值（非单 seed）、算 PRD、转成排名
   - 训练集做选择、测试集做验证，严格隔离
   - 这是"信号"来源，信号脏，整个进化就瞎

5. 进化器 / 种群管理（Evolver）
   - 职责：种群管理、选择、精英保留、多样性控制
   - 选择：top-K 精英
   - 多样性：相似度惩罚 / 帕累托，防止塌缩
     （"永远最好"现象就是这里缺了）
   - 这一层是"搜得动还是搜不动"的关键

6. 记忆库（Archive）
   - 职责：把进化中"为什么好"沉淀下来，跨代复用
   - 内容：历史最好解 + 一句"洞察"
     （如"这个邻域在瓶颈分散的实例上特别有效"）
   - 洞察文本可喂回 prompt，让 LLM 基于经验而非从零想
     （ReEvo 核心思想）

7. 自训练回路（Self-training）
   - 职责：外环，用进化数据微调 Qwen
   - 关键：在多样性做对之后才启动，
     训练样本要保留多样解，否则固化塌缩

==========================================================
三、数据流（一次完整的"一轮"）
==========================================================

实例集(训练) ──┐
              ├──► 评估器：对种群里每个算法跑多 seed ──► PRD/排名
              │                                              │
              │                    （排名 + 当前最优配置）     │
              │                                              ▼
              │                                    LLM引擎：变异/交叉/生成
              │                                              │
              │                                    新候选(算法配置/算子代码)
              │                                              │
              └──────────────────────────────────────────────┘
                        ▲
                        │
              进化器：选择 + 多样性控制 → 下一代种群
                        │
              （每代顺手把好解+洞察写进 Archive）

一句话：实例 + 算法 → 分数 → 反馈 → 新算法 → 再评估，
转起来就是内环；把内环产出的 (实例, 好算法) 对攒下来，
就是外环的燃料。

==========================================================
四、关键设计决策（现状 vs 建议）
==========================================================

决策点     | 现状       | 建议                | 影响
-----------|------------|---------------------|------------------
表示       | ID 串      | JSON → 代码片段     | 决定搜索空间大小
生成能力   | 只选       | 变异/交叉/新造      | 能否突破菜单天花板
评估       | 单 seed    | 多 seed + 排名      | 信号是否可信
种群       | 精英保留   | 精英 + 多样性控制   | 会不会塌缩
记忆       | 无         | Archive + 洞察      | 能否跨代积累经验
自训练     | 直接用生成 | 多样数据 + 时机控制 | 强化探索还是固化塌缩
           | 数据       |                     |

==========================================================
五、迁移路径（分阶段，别一步到位）
==========================================================

阶段 0（已在）：ID 选 + 单 seed + 精英保留
阶段 1（最小改动）：表示换成 JSON、评估改多 seed + 排名
        → 让"信号变干净、空间可编辑"
阶段 2：LLM 上变异/交叉（轻/中档）
        → 让循环真正"动起来"
阶段 3：加重变异（新造算子）+ 多样性控制
        → 突破菜单天花板、防塌缩
阶段 4：加 Archive/洞察 + 接自训练回路
        → 让系统真正"自进化"

每一步单独验证一个效果，不要一口气全上，
否则不知道是哪个改动起的作用。

【RSI 叙事定位（2026-08-31 补充）】
- RSI = Recursive Self-Improvement（递归自我改进）：
  模型用自己产出的数据训练自己，反复多轮。
  与项目的关系：现有系统是"弱版"——进化只改进算法，
  LLM 本身不变；完整 RSI 是"强版"——模型被自己的
  进化数据微调、再生成、再微调（= 自训练闭环）。
- 论文里怎么加（无需额外实验，纯叙事包装）：
  ① Intro 末尾 1-2 句："本文工作可视为 RSI 在算法
     设计领域的实例：模型生成算法、由可验证评估环境
     打分、并用进化数据强化模型自身。"
  ② Related Work 半页小节：RSI 背景 + 一句定位
     "现有 RSI 集中在语言任务且面临模型塌缩；算法
     设计场景有天然可验证奖励，我们提出防塌缩机制。"
  ③ 自训练章节开头：把 DPO/RLVR 方案表述为
     "RSI 的闭环实现"。

  Good 1965（智能爆炸思想源头）

八、研究 Idea 清单（2026-08-31，按性价比排序）
==========================================================

Idea 1：把 naive SFT 换成"偏好对齐"（DPO/GRPO）【最推荐】
- 进化过程天然产生偏好对："变好的变异" vs "变差的变异"
- 用偏好对做 DPO/GRPO，教模型"什么样的算法更好"，
  而不是教它"复读塌缩后的数据"
- 天然抗塌缩：偏好对含大量失败样本，模型学到比较能力，
  不是复制单一策略
- "用进化数据做偏好对齐来训练算法设计模型"
  目前文献没有成熟先例，创新性立得住
- 这是论文"自"字的核心实现

Idea 2：从"一个算法打天下"升级为"每实例自适应"【第二篇核心】
- 目标：进化出一个"算法池" + 训练"按实例特征选算法"的选择器
- 实例特征喂给 LLM：瓶颈负荷、加工时间方差、机器数、
  工件数分布等
- 对每个实例，LLM 挑池子里最合适的算法（或现场组一个）
- EoH-S / HeurAgenix 方向 + 自训练闭环 = 新组合
- 选择器复用第一篇自训练出来的模型，两篇叙事连续

Idea 3：规模泛化研究【最便宜、最好写、审稿人爱看】
- 小实例上进化 → 直接拿大实例验证
- 回答"LLM 学到的算法结构能否跨规模迁移"
- 结果正负都可写：正的是卖点，
  负的引出"为什么需要每实例自适应"（联动 Idea 2）

Idea 4：多样性消融做成机制论文的一章
- 定义多样性指标：组件组合熵 / 算法结构 edit distance /
  唯一结构数
- 消融：有多样性控制 vs 无
- 用数据证明"塌缩是 LLM 算法进化的通用失败模式，
  而 X 机制能缓解"
- 让工作从"工程报告"升格为"科学发现"

Idea 5：同预算公平对比框架
- 与 SMAC/irace 用相同评估预算（总跑批次数相同）
- 画预算-质量曲线
- LLM 若能在少样本条件下追上配置器 =
  "LLM 用先验换样本效率"的干净贡献

Idea 6：多目标 + 能耗【远期】
- HFSP 加能耗/准时交付变多目标，LLM 生成多目标算法
- 等单目标版本发出后当第二篇之后的第三篇
