## 1. 出发点:为什么换方向

背景实验事实(前几日确立):
- **组件菜单方式走不通**:LLM 在 AlgorithmSpec(枚举配置)上变异 ≈ 随机变异,行为拉不开、策略塌缩、oracle gap≈0。
- 根因推断:组件把行为压扁(都退化成 IG 式局部搜索),瓶颈在**表示层**,不在搜索层。

**当日方向锁定**(用户拍板,记入 memory):
- **弃组件菜单,改"中立骨架 + 机制槽"**:槽是 LLM 生成的**代码**,SA/GA/IG 只是槽代码的涌现结果,不是骨架的前置模板。
- **先 HFSP 完整跑通,VRP 后置**(架构纪律从第一天焊死:槽契约只认 `(perm, rng, ctx)`,VRP 来时不重构槽)。
- 每轮实验**都先量化成本/ETA**,不做盲目长跑。

## 2. 架构设计(落到代码前先对齐)

### 2.1 概念演进(对话中逐步收敛)
- "多槽"≠ 在 SA/GA/IG 模板上挖槽,而是**通用循环**:`construct / move / accept / anneal` 四个槽,骨架只做可信控制流。
- 用户补充:"告诉我扰动的语义(role),让 LLM 能自己改进 prompt/contract" —— 治"LLM≈随机"的病根:给槽语义角色,解锁 LLM 的优化先验。
- 定案:**CodeSpec = contract(每槽语义说明) + slots(代码) + params**,contract 随精英存活可被 LLM 改写。

### 2.2 中立骨架(NeutralSkeleton)
```
perm0 = construct(ctx, rng)          # 槽① 初始解(默认 ctx.neh())
for it in 1..max_iter:               # 可信控制流
    if 超时: break
    cand_perm = move(cur.perm, ctx, rng)      # 槽② 造候选
    cand      = decode(cand_perm)
    if accept(cand.ms - cur.ms, T, it, ctx, rng):   # 槽③ 接受?
        cur = cand
    T = anneal(T, it, ctx)            # 槽④ 降温(缺省几何)
    # 每隔 ls_every 代对 best 做一次 LS 深潜(仅小实例, 大实例跳过保评估成本)
```
- 文件:`hfsp/llm/codegen/skeleton.py`
- 关键决策:骨架**内置周期性 LS 深潜**(可信代码)——实测没有它种子间无区分度(swap/insert/inverse 全收敛同值),有它才能拉开(block 10.5% vs scramble 13.4%)。
- LS 仅 n≤80 实例启用(n≥120 时 LS 无时间参数会超时失控)。

### 2.3 CodeSpec 表示
- 文件:`hfsp/llm/codegen/spec.py`
- 4 槽契约 + `DEFAULT_CONTRACT`(语义说明初稿,LLM 会改写)。
- 字段:`{name, contract:{construct,move,accept,anneal}, slots:{...code}, params}`

### 2.4 ctx(DomainContext)—— 可信原语层
- 文件:`hfsp/llm/codegen/ctx.py`
- 给槽的只读世界:实例统计(num_jobs/stages/machines/pt) + 已验证算子原语。
- **关键设计:move 优先"编排已验证原语"而非裸写索引** —— 越界/重复是代码被拒的头号原因。
  - `ctx.perturb_once / perturb_n / apply_op(name,...) / list_ops() / makespan_of(perm) / neh()`
  - `ctx.exp/log`(免 import math)
- decode 预算硬上限(防失控循环 move),默认 40000/实例。
- **NEH 磁盘缓存**(`results/llm/neh_cache/*.npy`):NEH 是 O(n²) 且与 spec 无关,160-job 单算 25s;磁盘缓存后二次命中 0s。这是并行评估能跑的必要优化。

### 2.5 sandbox(合法率防线)
- 文件:`hfsp/llm/codegen/sandbox.py`
- AST 白名单(py3.14 节点兼容:Del/Delete、NotIn/In 新旧名都放行)+ 禁 import/IO/危险内建 + 行为校验(构造/扰动必须返回合法排列、move 不得改输入、accept/anneal 类型对)。
- `compile_slots(slots, ctx)` → 编译并行为校验全部槽。
- 教训:行为校验**别用 n=3/5/7 这类现实不存在的极小长度**测 move(会误杀按真实 HFSP 写边界的代码);用真实 n 和 n//2。

### 2.6 CodeMutator + 提示
- 文件:`hfsp/llm/codegen/mutator.py`, `hfsp/llm/codegen/prompts.py`
- 提示含:完整 parent CodeSpec + fitness + **contract(语义)** + ctx API 说明 + 正确用法示例。
- 变异分档:
  - light:只改 2-3 行/换 ctx 算子(保守);
  - medium:结构不同(移除-重建/复合/自适应强度)← 主攻;
  - heavy:可重写 contract + 全部槽。
- **错误回传**:retry 时把上次失败原因喂回 LLM —— 这是合法率从 ~0 拉到能用的关键杠杆。
- **API 正确用法示例**(治 `apply_op('perturb_once')`、`list.insert` 传错参)——把首次失败率从 ~67% 拉到 3/3 一次过。

### 2.7 种子池(同骨架基线)
- 文件:`hfsp/llm/codegen/seeds_code.py`
- 6 个种子 = 组件算子 code 化(swap/insert/inverse/block/scramble)+ 一个示范编排风格(seed_orchestrator)。
- 与 LLM 生成物**同构**(都是 code),同一 NeutralSkeleton 跑 —— 谁 RPD 低 = 谁 move 好,无骨架差异污染。

### 2.8 数据落盘(为后训练准备)
- run 脚本:`scripts/run_code_evolution.py`
- 每 run 落 `results/llm/code_run/<run>/`:
  - `meta.json`(骨架定义+槽schema+实例集+rho+bks)
  - `artifacts.jsonl`(每个 CodeSpec:code_id/source/parent/gen/contract/slots/params)
  - `evals.csv`(**细粒度**:code_id,instance,seed,makespan,rpd —— 与 oracle_gap 的 results.csv 同 schema,一表两用:诊断 + 后训练 reward)
  - `best_code.json` / `convergence.json` / `evolution_curve.csv` / `seed_baselines.csv`
- 原则:**存最细粒度,后训练(SFT/DPO/RLVR)离线再切**,bks/实例集变也能重算。
- 并行评估:fork pool + 模块级 worker(仿 evolve.py),`--jobs N`。

## 3. 关键实现决策(踩过的坑 → 修法)

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | sandbox 拒一切(Module/Del/NameConstant) | py3.14 AST 节点改名(Del≠Delete、NameConstant 并入 Constant) | 新旧名都放行 + getattr fallback;测出真实节点类 |
| 2 | NEH 起点 25s×每 spec | NEH O(n²) 且与 spec 无关 | 磁盘缓存(`neh_cache/*.npy`),二次 0s |
| 3 | 骨架 25s/大实例"超时" | **不是循环慢,是开头 construct 里 NEH 25s** | NEH 缓存解决 |
| 4 | 大实例 LS 失控 | local_search 无时间参数,无改进扫全邻域 | LS 仅 n≤80 启用 |
| 5 | 行为校验误杀(小长度 low>=high) | 用 n=3/5/7 测,现实不存在 | 改用真实 n、n//2 |
| 6 | light 变异"只改参"无增益 | g1 只把 steps 2→3,结构不变 | medium 主导(60%)+ 父代掺随机防近亲 |
| 7 | medium 首次失败率高(~67%) | LLM 记不住 ctx API(apply_op 名、insert 传参) | SYSTEM 加"正确用法示例" → 3/3 一次过 |
| 8 | 并行 worker 各自算 NEH | fork 各自继承一份 | 磁盘缓存跨进程共享 |

## 4. 实验记录与结果

### 4.1 单槽 pilot(前几轮,已废)
- LLM 生成单 perturb → sandbox → SA 骨架 → 10-job makespan。合法率 1/1,但纯贪婪无区分度。已被多槽版取代(pilot.py 删除)。

### 4.2 合法率 / 模型对比
| 模型 | 变异方式 | 合法率 |
|---|---|---|
| qwen2.5:14b(通用) | light | ~50%,fell_back 多 |
| **qwen2.5-coder:14b** | light | **5/6 = 83%**,0 fell_back |
| qwen2.5-coder:14b | medium(加 API 示例后) | 3/3 一次过 |

- 结论:**换代码专用模型(coder)比一切提示工程提升都大**。硬件 Apple M4/16GB 上限 = 14b coder(32b 放不下)。

### 4.3 mid2(20 实例跨 10-160,pop6,gen2, 旧 light 变异)
- 种子 best = seed_orchestrator **5.727%**(编排原语 > 全部单算子)。
- 但 LLM 孩子全 ≤ orchestrator,曲线 5.73→5.73→5.73,**进化无增益**。
- 诊断:light 只改参(g1 只把 steps 2→3)+ 孩子退回 scramble → 变异被保守约束阉割。

### 4.4 mid3(同规模,gen3, medium 主导)
- 曲线 5.913→5.913→5.913→5.907,≈无增益。
- 诊断:medium 自由度让 LLM 记不住 API,首次失败率 ~67%,有效孩子太少。

### 4.5 mid4(同规模,gen3, medium 主导 + API 正确用法示例)
- **进化增益确立**:种子 best(seed_insert)5.913% → **进化 best(g2)5.742%**,curve 5.91→5.91→5.74→5.74。
- g2 move = LLM 写的 **destructive-reconstructive block move**(随机移除 block + `ctx.makespan_of` 贪心找最优插回),结构上超过所有手写种子 —— 这正是"代码生成在进化中发明更强结构"的证据。
- 合法率:calls 12, legal 10, fell_back 2;耗时 24.6 min(gen3)。

## 5. 三条站得住的实证(今日核心收获)

1. **代码槽表示能超过组件**:seed_orchestrator(编排原语)和 mid4 的 g2(破坏-重建)都赢了全部组件算子种子。

3. **全套基建可用可复现**:sandbox / ctx / NeutralSkeleton / CodeMutator / 并行评估 / NEH 磁盘缓存 / 细粒度落盘(artifacts+evals)都到位,coder 模型合法率 83%。

## 10. 给未来的提醒(避免重蹈)

1. **代码生成合法率瓶颈 = 模型代码推理能力**,不是提示能根治;换 coder 模型是最大杠杆。
2. **变异自由度 vs 合法率是跷跷板**:light 安全但无增益,medium 有效但易写错 → 用"medium 主导 + API 示例 + 错误回传 + 选择把关"。
3. **评估成本大头是 NEH 构造**(非骨架循环),大实例尤其;NEH 缓存 + 进化集上限(--max-jobs)是必要的。
4. **LS 无时间参数会在大实例失控**,骨架里按 n 分档。
5. **进化评估用快而糙的设置(小 pop/降迭代),最终结论再上精确评估** —— 否则排序噪声会淹没小改进。
