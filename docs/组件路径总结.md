# 组件路径总结(收尾)

> 组件路径(LLM 在固定组件菜单里做配置进化)整条线的工作总结。**这是该路径的最终结论文件**;
> 细节展开在 `组件提示词工程盘点.md`(提示词 9 机制)。读过本篇即可理解"做了什么、为何到此为止"。
> 整理日期:2026-09-07。**本篇标记组件路径正式收尾。**

---

## 0. 一句话结论

> **组件路径做足、证据齐、到此为止。** LLM 作为"受约束配置变异算子",在 ~20 项组件的封闭菜单里做有界选择;
> 它确实能稳定改进配置并逼近种子最优,但**顶区平坦,价值上界 ≈ IG 级(结构突破不了种子模板)**。
> 提升真正的地板不在提示词(词典/few-shot/反思都试过、都只带来零点几增益),而在**表示方式** —— 交给"骨架+代码槽"路径。

---

## 1. 组件路径是什么

**LLM 定位:不是代码生成器,是一个「受约束的配置变异算子」—— 用来替换随机变异 `perturb_spec`。**

- 设计空间 = 固定白名单:`AlgorithmSpec`(JSON)= 结构开关(population_mode / use_destroy_repair)×
  初始化器 {neh, spt, lpt, palmer, cds, random} × 变异算子 {swap, insert, inverse, scramble, block} ×
  交叉算子 {ox, pmx, two_point} × 接受准则 {always, only_better, metropolis, threshold, record_to_record} × ~10 个数值参数。约 20 项。
- 四条可分派模板:GA / IG(destroy&repair)/ 单解搜索(SA-ILS 式)/ 纯构造(max_iterations=0)。
- 每步只做一件事:给定父配置(JSON)+ 反馈(标量 fitness/rank/pop_best/reflection/insight),吐一个改进的 `AlgorithmSpec`。

**对比(为什么要换表示):** 代码槽路径让 LLM 生成**算子代码**(`hfsp/llm/codegen/`,骨架+槽),设计空间从"菜单里挑"
变成"代码空间里生成",突破组件路径的天花板。本篇只管组件路径的收尾。

## 3. 最终实验证据(词典 ON)

### 前置修复(2026-09-07,已提交 2871fcc)

- **时间预算 bug**:原 `time_limit=max(budget(i))` 把最大实例预算塞给**所有**实例 → 小实例空烧 ~4x
  (实测 n=10 解给 2.36s 与 0.3s 结果一样)。改为 **per-instance** 预算(`make_fitness` 加向后兼容 `time_limits`),
  对齐论文协议 `t=rho*n*m/1000 per solve`。gen0 从 1h+ 降到 ~3.5min。
- **fast 训练子集**:`benchmarks/seville/split/evolution_train_fast.txt` = 32 实例(n≤80,砍 n=120/160,
  NEH init 从 ~82s 降到 ~5s),解决大实例 NEH 初始化无视时间上限卡死 gen0 的问题。

### 全实验(base_run_sem,词典 ON)

**配置**:fast 子集 × pop8 × gen10,rho=0.5,n_runs=3,seed=42,jobs=6。耗时 61min。

```
种子基线(重估): GA 11.49 | IG 6.07 | SA-like 6.76 | NEH+LS 6.35
best 曲线:      +6.34 → +6.04 → …(顶区平台)→ +5.83 (g9)
```

- **best g9 = +5.83%,比最优种子 IG(6.07)低 0.24pp**。结构:IG 式(pop=false, destroy&repair=true)
  + **cds 初始化 + threshold 接受(0.15)+ 局部搜索 60 次** —— 顶区平台内的局部再优化。
- **LLM 合法率 60 calls / 0 failed / 0 回退父代**:词典+输出侧安全网在真实进化里零失误。
- 种群 diversity 0.75–1.0,无塌缩;mean 曲线有噪音但 best 单调收敛。

**对照**:历史无词典 run(`results/llm/base_run/`,40 实例含 n≤160,4.42→4.17)因**子集+预算策略不同,
绝对 RPD 不可比**,且旧管线结果已按 `8c37d4f` 作废,仅存档备查。真正可比的是"词典 ON 相对种子基线 +0.24pp"这个事实。

## 4. 为什么到此为止(核心结论)

1. **顶区平坦**:收敛后所有好配置都落在 IG 级 —— 结构被种子模板锁死,LLM 在菜单里换配件
   (cds 初始化、threshold 接受、加 LS)只能抠零点几 pp。
2. **提示层学习≈0**:few-shot 消融(B)已证无增益;词典(full 全量塞 prompt)也只带来本次这 0.24pp;
   反思/insight 是唯一起作用的自适应机制,但也越不过结构天花板。
3. **设计空间太小是根因**:~20 项白名单的"上界"由"封闭菜单"决定;菜单本身不产生新结构。
   所以提示词工程(9 机制)做足也改变不了结局 —— **这是表示问题,不是提示问题**。
4. RAG / CoT 判断:组件空间小、词典全量静态塞入正好(= 全覆盖检索极限形态),**不上 RAG**;
   CoT 受 `format=json` 限制只能做 structured `reasoning` 字段,**可选未上**,天花板照旧。

> 一句话:**组件路径的价值上界 = "封闭菜单 + 顶区平坦";真正的提升在代码槽路径(LLM 生成算子代码)**。

## 6. 交接(给代码槽路径)

- 组件路径的**对照基线保留**:代码槽实验要"同骨架、同超参、同初始解"下对比组件算子 code 化 vs LLM 生成的槽代码。
- 组件管线的坑(codegen 复用时注意):
  - 时间预算用 **per-instance**(`t=rho*n*m/1000 per solve`),别用 uniform-max;
  - 大实例 NEH 等初始化无视 time_limit,训练子集要控制 n 或修执行器;
  - LLM 输出必须 sandbox/repair/validate + 回退父代(组件路径 60/0/0 就是这么保住的)。
- 方向(据 2026-09-03 锁定):弃组件菜单 → **中立骨架 + 机制槽(LLM 生成代码)**,HFSP 先完整跑通,VRP 后置。
  见 `docs/会话记录_20260903_骨架代码槽.md` 与根目录方案 txt。
