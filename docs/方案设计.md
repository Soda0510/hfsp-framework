## 旧版 · 总览:两件事(历史)

> **核心:我们其实在做两件事——生产一个算法,以及训练一个生成器。这两件事是分开的、各自独立的贡献,必须分开讲。**

---

## 0. 总览:两件事

| | **线程 A · 生产一个算法(+参数)** | **线程 B · 生成器** |
|---|---|---|
| 做什么 | 用 LLM 进化的方式,**搜出一个算法**(g1)及其参数 | 把 LLM **训练成一个生成器**:给定算例 → 生成针对性算法 |
| 产出物 | 一个具体的算法(g1) | 一个可复用的生成能力(LLM 本身) |
| LLM 的角色 | **搜索算子**(变异器) | **生成器本体**(被部署的能力) |
| 回答的问题 | "能自动设计出与 SOTA 竞争的算法吗?" | "能学会按算例定制算法吗?" |
| 学术对应 | 元层进化 / 自动算法设计 | Algorithm Selection / Learning to Optimize |

**这两件事不是同一个,也不是一个取代另一个——是递进的两步:**
```
线程 A: 进化 → 产出 g1(算法)
线程 B: 用 A 的进化经验微调 LLM → LLM 成为生成器 → 按算例生成算法
         ↑ 微调(后训练)把 A 和 B 连起来
```

---

## 1. 线程 A · 生产一个算法及参数

### 1.1 本质:元层进化(超启发式)

```
层级0 解:        一个作业排列 → makespan
层级1 算法:      一个元启发式(AlgorithmSpec)→ 在层级0上搜索解
层级2 元进化:    LLM 当变异算子,在"算法空间"上进化 → 产出 g1
```

| | 传统元启发式(GA/IG/SA) | 线程 A |
|---|---|---|
| 进化的是什么 | **解**(作业排列) | **算法**(AlgorithmSpec) |
| 搜索空间 | 解空间 | 算法设计空间 |
| 评估 | 解码 → makespan | 跑算法 → RPD |

### 1.2 机制
- **组件组合式设计空间**:算法 = 结构 × 组件 × 参数(`AlgorithmSpec`),LLM 只改配置不写代码 → 确定可复现
- **可配置执行器**:spec → 可运行求解器(四模板)
- **进化框架**:种群(种子+随机)→ 评估(RPD vs UpperBounds)→ 选择 → LLM 变异
- **反馈 + 反思**:把 makespan 反馈与点评喂进变异提示

### 1.3 线程 A 的创新点
- 组件组合式设计空间(区别于 EoH/ReEvo 的代码生成)
- 静态 HFSP makespan + 标准 480 基准(该格无人占)
- LLM 引导的搜索 ≥ 随机搜索(靠消融证明)

---

## 2. 线程 B · 生成器

### 2.1 本质:LLM 是"可学习的生成器网络"

```
传统:  DRL 策略网络 φ(s) → 输出决策         ← 网络从零训练
线程B: LLM(预训练巨型网络)→ 输出算法配置    ← 天生会 + 可微调
```

**关键区分**:这不是"静态规则表"(算例→算法的死查表),而是**生成器/策略**——给定**任意**算例(其特征)→ 当场生成算法,**能泛化到新算例**。

### 2.2 LLM 作为生成器的三个独有特性

| 特性 | 说明 | 普通神经网络有没有 |
|---|---|---|
| **预训练先验** | 天生知道"破坏-重建/温度接受"等优化概念 | ❌ 从零学 |
| **In-context 推理** | 能读自然语言反馈 + 反思,"想清楚再生成" | ❌ 只能靠梯度 |
| **可微调(自改进)** | LoRA 微调,从进化经验里越学越会生成好算法 | 需从零大量训练 |

### 2.3 线程 B 的创新点
- **首次微调"设计算法的 LLM"自改进**(整条 EoH/ReEvo/FunSearch 谱系无人做)
- **按算例定制算法**(Algorithm Selection / Learning to Optimize 方向)
- 前提:要让生成器"看得见"算例特征(提示词需加算例表示)

## 3. 两条线程的连接

```
线程 A(进化)──产生──▶ 变异日志(父/子 spec + 真实 fitness)
                          │
                          ▼ 微调(后训练, LoRA)
线程 B(生成器)◀──微调后 LLM── 成为"会生成算法的生成器"
                          │
                          ▼ 按算例生成
                    每个算例的针对性算法
```

**一句话**:A 用 LLM 当工具造出一个算法;B 把 LLM 自己升级成"会造算法"的生成器。**A 的经验数据喂给 B 做后训练,A 是 B 的前提。**

---

## 4. 核心实验设计:三层次消融(论文灵魂)

**把 LLM 的价值拆成"预训练先验"和"后训练学习"两部分,分别量化。** 它同时服务两条线程:

```
层次0: 随机变异进化(或随机生成)     ← 无先验、无学习(基线)
层次1: 零样本 LLM                   ← 有预训练先验、无后训练
层次2: 微调后 LLM                   ← 有预训练先验 + 后训练(自改进)

层次0 → 层次1 = 预训练先验的作用
层次1 → 层次2 = 后训练自改进的作用
```

| 在线程 A 中 | 在线程 B 中 |
|---|---|
| 随机 vs 零样本:LLM 引导搜索是否优于随机 | 随机生成 vs 零样本生成:先验是否让生成更好 |
| 零样本 vs 微调:后训练是否让搜索更好 | 零样本 vs 微调:后训练是否让生成器更会设计 |

| 审稿人问题 | 用哪层对比回答 |
|---|---|
| 为什么用 LLM,随机不行? | 层次0 vs 层次1 |
| 你喂的数据(微调)有用吗? | 层次1 vs 层次2 |
| LLM 是不是可有可无? | 整张表:两步提升都有 |

**实现映射**:层次0 = `perturb_spec`;层次1 = 零样本 LLM(已跑,得 g1);层次2 = M8 微调。

## 5. 论文定位与题目

### 5.1 一句话定位

> 我们做两件事:① 用 LLM 引导的元层进化,在组件组合空间上**自动设计出与 SOTA 竞争的 HFSP 元启发式**;② 首次让这个 LLM 从自己的进化经验中**微调自改进**,成为**按算例生成算法的生成器**。

### 5.2 题目

> **《学习设计元启发式:面向混合流水车间调度的大语言模型元层进化与自改进》**
> EN: *"Learning to Design Metaheuristics: LLM-Guided Meta-Level Evolution with Self-Improvement for Hybrid Flow Shop Scheduling"*

### 5.3 贡献清单

**线程 A(算法生产)**
1. 组件组合式设计空间 + LLM 元层进化(区别于代码生成,确定可复现)
2. 静态 HFSP makespan + 标准 480 基准上,自动设计算法 ≥ IG

**线程 B(生成器)**
3. 首次微调设计算法的 LLM 自改进(整条谱系空白)
4. 按算例定制算法的生成器(Algorithm Selection / Learning to Optimize)

**共同证据**
5. 三层次消融,量化预训练先验 vs 后训练学习

| **P5d 正式测试**(144 黑盒, ρ=2) | g1 **5.96%** < IG 6.12%, Wilcoxon **p=0.0078**, Friedman p<0.0001 | **LLM 进化算法统计显著优于 IG(头条实证)** |

## 实验协议(2026-08-31 冻结, M4 优化)

> 以下协议已冻结,新管线的所有实验(基座/随机/消融)统一使用,一次定对避免重跑。

| 参数 | 值 | 说明 |
|---|---|---|
