## 1. A 族 — 正式基准 `benchmarks/seville/`

来源:Fernández-Viagas & Framinan (2020) HFSP testbed(塞维利亚大学官方页),本地副本。
论文:`Design of a testbed for hybrid flow shop scheduling with identical machines`, C&IE 141 (2020) 106288.

| 路径 | 内容 | 规模 | 说明 |
|---|---|---|---|
| `instances/small/` | `instancia_<n>_<s>_<idx>.txt` | 240 个 | n∈{10,15,20,25,30,35}, s∈{5,10,15,20}, idx 1..10 |
| `instances/big/` | 同上命名 | 240 个 | n∈{40,80,120,160,200,240}, s∈{5,10,15,20} |
| `references/UpperBounds_01_April_2019.xlsx` | 逐算例上界(=RPD 分母) | 480 行(2 sheet) | sheet `Big_Size`/`Small_Size`,列 `n,s,Instance,Cmax` |
| `split/train.txt` | 336 实例名 | 训练 | 每 (n,s) 层 idx 1..7 |
| `split/test.txt` | 144 实例名 | 测试(黑盒) | 每层 idx 8..10 |
| `split/evolution_train_subset.txt` | 40 实例名 | 进化实际训练子集 | 每层取 1(尺寸覆盖到 160) |
| `split/split.json` | 划分元数据 | — | 记录划分规则 |
| `README.md` | 基准说明 + 格式 | — | 权威格式文档 |

### 1.1 算例文件格式(每个 .txt)

```
<n作业数> <s阶段数>
<m_1 ... m_s>                 # 各阶段并行机数量(阶段内机相同)
<p_1_1 ... p_1_n>             # 阶段1 各作业加工时间,共 s 行
...
```

- 文件名 ↔ 上界表键:`instancia_<n>_<s>_<idx>` ↔ `(n, s, Instance=idx)`。
- 机数参考:small `10_5` 为 `[3,3,2,3,3]`(即 5 阶段、合计 14 机);big `240_20` 每阶段 3 机 × 20 阶段。

### 1.2 时间预算公式(全仓库统一,勿改)

```
time_limit = rho × n_jobs × total_machines / 1000   # 秒
```
`rho=2` 用于正式测试评估;`rho=0.5` 用于进化内评估(便宜);`rho=10` 曾用于小样本基线。出处:`scripts/run_baselines.py:95` `_budget()`。

### 1.3 代码读写入口

- 读实例:`hfsp/io/seville.py` → `SevilleReader`(root=`benchmarks/seville`);`SevilleReference` 读 xlsx 上界。
- 读划分:`hfsp/llm/dataset.py` → `stratified_split / evolution_train_subset / kfold_split`。
- 完整验证:`scripts/verify_seville.py`。

## 3. C 族 — LLM 实验结果(产物)`results/llm/`

> ⚠ **`results/` 在 `.gitignore`,不随 git 走**——重跑即可再生。每跑一次进化会**覆盖** `base_run/`,历史版本若不手动改名会被冲掉(现状:`base_run_old20` 即旧版手动保留)。

### 3.1 目录速查

| 目录 | 代表产物 | 对应脚本/阶段 | 说明 |
|---|---|---|---|
| `base_run/` | 当前进化主跑 | `run_evolution_full.py`(P5c/新管线) | best_spec + convergence + curve + mutation_log + seed_baselines |
| `base_run_old20/` | 旧版主跑(手动保留) | 同前(早期) | 内容/结构同上,旧 20 子集时代 |
| `ablation_random/` | 随机变异对照 | `run_ablation_random.py`(层次0) | 无 LLM 先验的对照 |
| `fewshot/` | 少样本对照 | `run_ablation_fewshot.py`(B) | best_spec + 示例(examples.json) |
| `oneshot/` | 一次性 LLM 设计 | `run_oneshot.py`(F) | oneshot_spec + 快速评估 |
| `p5d/` | **正式测试评估** | `run_p5d.py` | 144 测试集 RPD 表 + 统计检验 |
| `e_top10/` | top-10 组合 | `select_top10.py`(E) | 判断 top 是否多样(近克隆) |
| `evidence2/` | 防塌缩证据2 | `verify_evidence2.py` | baseline vs anti_collapse |
| `test_evals/` | 单 spec 测试评估 | `eval_spec_test.py` | 每文件 = 1 个 spec 在 144 测试集 |
| `figures/` | 论文图 | `plot_results.py` | fig1 收敛 / fig2 RPD 对比 |

### 3.2 各产物文件 schema(逐文件)

#### `best_spec.json` — 进化产物(AlgorithmSpec)
单条 JSON,键即 AlgorithmSpec 字段:`name, population_mode, use_destroy_repair, initializer, mutation_operators[], crossover_operators[], crossover_prob, mutation_prob, acceptance, temperature, threshold, cooling_rate, use_local_search, local_search_iterations, population_size, max_iterations, elite_size, tournament_size, destruction_size`。

- `base_run/best_spec.json`:name=`g9`,单解 + destroy-repair,initializer=`cds`,5 个变异算子 + 3 交叉,metropolis + cooling,local_search=80 iters。
- 读:`hfsp/llm/representation.py` `spec_from_dict()`。

#### `convergence.json` — 代际收敛
键 `history`(每代 best RPD)、`history_mean`(每代种群平均)。`fewshot` 版只有 `history`。

#### `evolution_curve.csv` — 进化曲线(便于画图)
列:
- `base_run`:`generation, best_rpd, mean_rpd, diversity`
- `base_run_old20` / `ablation_random`:`generation, best_rpd, mean_rpd`(无 diversity 列)

例:`base_run` 11 行 gen0-10,best 收敛 4.42→4.17;`base_run_old20` 21 行,best→4.11;`ablation_random`→4.14。

#### `seed_baselines.csv` — 初始种子算法的 RPD(进化内参考线)
列 `seed, rpd`,4 行:GA / IG / SA-like / NEH+LS。两套 base_run 数值不同(不同训练子集/时期)。

#### `mutation_log.jsonl` — 变异日志(**微调训练数据来源,最重要**)
每行一条变异事件。键(新管线):
`gen, parent(full spec dict), child(full spec dict), parent_fitness, mode`
- `base_run/mutation_log.jsonl`:60 条,gen 1..10。
- `base_run_old20/mutation_log.jsonl`:120 条,gen 1..20,**无 `mode` 键**(旧格式)。
- 读:`select_top10.py` 用它收集历史 spec;计划做 DPO/偏好对也用它(parent 差,child 好的 → 偏好对)。

#### `p5d/` — 正式测试(144 黑盒, ρ=2)
- `rpd_table.csv`:列 `algorithm, instance, rpd`,7 算法 × 144 实例 = 1008 行。算法:`Evolved(g1), IG, GA, SA, DPSO, NEH+LS, NEH`。headline:g1 5.96 < IG 6.12。
- `summary.json`:各算法 mean/min/max + `head_to_head`(win/loss/tie)+ `wilcoxon` p + `friedman`。g1 vs IG p=0.0078。

#### `e_top10/top10.csv` — 结构化 top-K(看是否近克隆)
列:`rank, name, rpd, pop, destroy, init, accept, ls, mut_ops, max_iter, pop_size, temp, cool, d_size`。10 行。rpd 在**训练子集**(ρ0.3)下评,不是测试集。

#### `evidence2/evidence2.json` — 防塌缩对照
键 `baseline` / `anti_collapse`,各含 `best, history[], diversity[]`。
- baseline best 5.281;anti_collapse best 4.895 → 防塌缩版更低(有利证据2)。

#### `oneshot/`
- `oneshot_spec.json`:一次性让 LLM 设计的 spec(种群版,population_mode=true)。
- `oneshot_eval.json`:10 实例快速评估。oneshot mean 7.85 vs g1 6.96(g1 赢 1/10)。

#### `fewshot/examples.json` — 少样本示例
list,每项含 `parent / child`(成功改好的真实例子),长度 3。

#### `test_evals/` — eval_spec_test 输出
每文件列 `algorithm, instance, rpd`,144 行(全测试集)。命名含 spec 名 + 版本后缀:

| 文件 | algorithm | 测试集 mean RPD | 备注 |
|---|---|---|---|
| `g1_new2_rpd.csv` | g1_new2 | 5.921 | 新管线 g1 复评 |
| `g1_new_rpd.csv` | g1_new | 6.002 | |
| `g10_new2_rpd.csv` | g10_new2 | 5.603 | 新管线 g10 复评 |
| `g10_new_rpd.csv` | g10_new | 5.978 | |
| `g10_rpd.csv` | g10 | 6.057 | 旧 |

#### `figures/` — plot_results.py 产物
`fig1_evolution_convergence.png`(收敛曲线)、`fig2_rpd_comparison.png`(测试集 RPD 对比条形图)。

## 5. 常见坑速查

1. **`results/` 会被覆盖**:重跑进化前,若当前 `base_run/` 还要用,先 `cp -r` 成 `base_run_oldXX`(项目就是这么留 `base_run_old20` 的)。
2. **上界表是 2019-04 旧值**:若某算法 PRD<0 说明破了 BKS,先查是表旧还是 bug(见 Oracle 方案)。
3. **`InstanceReader("Data")` 现在指向空目录**(Data/ 已删,见 §2)。要用 seville 数据请走 `SevilleReader`,别混用两套实例格式。
4. **seed 不足**:历史 rpd 表大多无 seed 维度,做方差分解/胜者诅咒前必须补 seed。
5. **时间预算公式改动会影响所有可比性**,统一走 `_budget()`。
