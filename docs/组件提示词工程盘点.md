## 1. 组件路径中,LLM 的定位

**LLM 不是代码生成器,而是一个「受约束的配置变异算子」—— 用来替换随机变异 `perturb_spec`。**

- 设计空间 = 固定白名单(初始化器 × 算子 × 接受准则 × 超参)。
- LLM 每步只做一件事:给定父配置(JSON)+ 反馈,吐出一个改进后的 `AlgorithmSpec`(JSON)。
- 提示词的全部作用就两件:**圈住**(白名单 + 只输出 JSON + 必须与父代有实质差异)+ **导引**(fitness/rank/pop_best/reflection/insights 反馈)。

这个定位直接解释了组件路径的天花板:**LLM 在一个封闭菜单里做有界选择,顶区又平坦(全都收敛到 IG 级),提示词再打磨也突破不了。**

## 2. 已做的提示词工程(全部已接进进化循环)

| # | 机制 | 代码位置 | 说明 |
|---|------|---------|------|
| 1 | 专家 SYSTEM_PROMPT(白名单+规则) | prompts.py | 规则 3:"差→换结构;好→只调参"。给 LLM 的唯一设计直觉。 |
| 2 | 标量 fitness + rank + pop_best | evolve.py | 喂种群名次 + 距当前最优差,不喂裸 makespan。 |
| 3 | light/medium 分级变异 | prompts.py | mode 控制变异强度(light=换一个离散组件, medium=调一个数值参数);比例 0.3/0.6/0.1。 |
| 4 | crossover 提示词 | prompts.py | 两父代合并,偏好 RPD 更优一方的组件。 |
| 5 | ReflectionEngine「verbal gradients」 | reflection.py + prompts.py | LLM 当批评家,诊断配置好坏 + 改进方向,缓存后回喂。 |
| 6 | InsightArchive 跨代记忆 | archive.py | 每代问"当前最优为何有效",存 (config,fitness,insight),回喂下一代(ReEvo);兼作 DPO 原料。 |
| 7 | few-shot examples | prompts.py | 从进化日志取真实"父→子成功改进"当少样本。**B 消融 ≈ 无增益(4.18 vs 4.11)。** |
| 8 | heavy mutation(设计不执行) | prompts.py | 让 LLM 设计新算子,但明确拒绝执行 LLM 代码,只记 insight,保证可复现。 |
| 9 | 输出侧安全网 | mutator.py | spec_from_dict 强制 + repair + validate + 3×重试 + 回退父代。 |

## 3. 阶段7:组件语义词典(本次新增)

### 问题
SYSTEM_PROMPT 只给组件**名字和取值区间**,不给**语义**。LLM 靠预训练知识认词 —— 教科书词(NEH/metropolis/swap)认得好,但**歧义/特殊实现**认不准:`block`(整块搬移、长到 n/3)、`scramble`(打乱的是**连续子段**)、`record_to_record`(距历史最优 (1+r) 内接受)、以及**三模板分派**。

### 改动(已提交)
- `prompts.py`:`SYSTEM_PROMPT_BASE`(原白名单,未动)+ 新增 `COMPONENT_GLOSSARY`(逐条语义,从 hfsp/methods 真实实现抄写)+ `build_system_prompt(with_semantics)`,`SYSTEM_PROMPT` 默认带词典。
- `mutator.py`:`LLMMutator(use_semantics=True)`,构造时选系统提示词,三处调用(mutate/heavy/crossover)走 `self.system_prompt`。
- `run_evolution_full.py`:`--no-semantics`(关词典)/ `--tag`(输出目录后缀)消融开关。

### 自我批评
- 词典 80% 是 LLM 已知的教科书内容,真正增量只有 block/scramble/R2R/分派几行 —— 若做消融,应收窄为"只加歧义项"而非全量。
- 一处过度简化:写 metropolis "T cools by cooling_rate",但代码里**只在单解模板成立**,IG 模板 T 恒定。
- 形态判断:组件全集 ~20 项、词典 ~2KB,静态全量塞 system prompt 是对的(见 §5 RAG)。

## 4. 实验状态与决策(2026-09-07)

- **决定:跳过语义消融(off/on 对照),词典默认 ON,直接跑全实验。**
- 原因:few-shot(B)已证"提示层学习 ≈ 0 增益",瓶颈在设计空间顶区平坦而非缺知识;消融预期大概率 null,成本不划算。
- 相关待办:词典 ON 的全实验(gen/pop 按方案)尚未排期执行。

### 4.1 组件全实验(词典 ON)已完成 —— fast 子集(2026-09-07 夜)

- **前置修复**:原脚本 `time_limit=max(budget(i))` 把最大实例预算塞给所有实例,小实例空烧 ~4x(实测 n=10 解 2.36s 与 0.3s 同结果);已改 **per-instance 预算**(`make_fitness` 加向后兼容 `time_limits`),对齐论文协议 `t=rho*n*m/1000 per solve`。gen0 从 1h+ 降到 ~3.5min。
- **子集**:`evolution_train_fast.txt` = 32 实例(n≤80,砍 n=120/160,NEH init 从 ~82s 降到 ~5s)。子集文件随代码已提交 `2871fcc`。
- **配置**:pop8 × gen10,rho=0.5,n_runs=3,seed=42,jobs=6,词典 ON,use-reflection ON。耗时 61min(收尾+5min)。
- **结果**(`results/llm/base_run_sem/`,mean RPD vs UpperBounds):
  - best 曲线:+6.34 → +6.04 → … → **+5.83**(g9);种子基线 GA 11.49 / IG 6.07 / SA-like 6.76 / NEH+LS 6.35。
  - **best(g9) 比最优种子 IG(6.07)低 0.24pp**,是一个 IG 式结构(pop=false,destroy_repair=true)但换 **cds 初始化 + threshold 接受(0.15)+ LS 60** 的配置 —— 顶区平台里的局部再优化,符合"组件路径天花板≈IG 级"的判断。
  - LLM 合法率 **60 calls / 0 failed / 0 fell_back**(词典+输出侧安全网在真实进化里零回退);种群多样性 0.75-1.0 无塌缩。
- 存档:`results/llm/base_run_sem/`(best_spec.json / evolution_curve.csv / seed_baselines.csv / mutation_log.jsonl / convergence.json)+ log `results/llm/run_sem_fast.log`。

## 5. RAG 与 CoT 的决策(讨论结论,未实施)

### RAG —— 组件路径不上
RAG 解决的是"知识库大到塞不进上下文 + 每步只要一薄片"的问题。组件路径两者都不满足:
- 组件全集 ~20 项、词典 ~2KB,**全量静态塞 prompt 正好**;静态全量词典 = 全覆盖检索的极限形态。
- 每步变异都在全组件空间里选,词典**全部相关**,无检索必要性。
- 本地 14b 检索质量不可信,加管道反而引入新误差源。
- 真正值得 RAG 的地方是**代码槽路径**(检索历史槽代码 + 反馈,即跨代 memory),不是组件。

### CoT —— 组件路径可选,未实施
- 实现约束:`chat_json` 走 Ollama `format=json`,**自由文本 CoT 不可行**;可行形态是 structured field —— 输出 `{"reasoning": "...", ...配置}`,`spec_from_dict` 忽略未知键,解析零风险。
- 可能价值:对冲"惰性变异"(base_run 前三代 best 纹丝不动是策略塌缩微观形态),few-shot 做不到这点。
- 但预期天花板照旧:反思已部分承担诊断;few-shot 无增益是强反证;14b CoT 质量有限。
- 若要测:做成第三个臂 `--cot`,先小跑看是否更快离开平段。
